# 按记录身份重放一个点击

V9 增加两个独立能力：从一次选取中保存可见的记录身份；真实鼠标输入传播时继续核验身份。它可以替换固定点击的定位与执行部分，不负责理解自然语言任务、规划整个流程或判断服务器结果。

## 不写定位器

本地私密体验包的使用步骤见 [预览版说明](BINDING-PREVIEW.md)。在独立浏览器里找到目标，用 Option/Alt 点击选取，随后可以通过保存的 JSON 重放一个点击。录制和执行都不调用模型。普通点击仍按网页原本的行为操作；选择模式只拦截用于选取目标的那次输入。

## 接入 Python

```python
from deltadom import ActionBinding, guarded_click

binding, capture = await ActionBinding.capture(selected_locator)
if binding is None:
    print(capture)  # 没有足够的可见身份依据
else:
    saved = binding.to_json()
    # 可以保存到本地，再在同一网址加载。
    restored = ActionBinding.from_json(saved)
    receipt = await guarded_click(restored, page)
```

`capture` 的输入是使用者或现有工具已经选中的控件。它不会生成任务目标，也不读取评分器或隐藏业务 ID。

识别时优先保留最近上下文里能区分记录的可见链接地址和名称；没有链接时保留区分记录的文字。重放时重新编译最近上下文，要求层级和身份依据一致且唯一。不能扩大查找范围，直到在整个列表里找到一段旧文字就接受另一个按钮。若是页面中唯一的命名控件，也可保存唯一性约束。

真实点击通过 Playwright 输入发送。在从 window 到目标的事件捕获路径上安装短期核验监听器；页面变化时重新解析身份。监听器和缓存都会在操作结束后清理，不修改页面的业务处理函数。页面在 hover、按下或祖先捕获处理期间换掉记录时，可以在后续事件到达业务处理前阻止输入。完整诊断包含无法拦截的反例。

## 回执的含义

| 回执 | 含义 |
|---|---|
| `clicked` | 观察到通过身份检查的真实点击输入；没有核验业务结果 |
| `unresolved` | 当前没有唯一、相符的目标，未开始点击 |
| `blocked` | 输入传播中发现变化并拦截后续传播；不能撤销较早处理函数已产生的副作用 |
| `uncertain` | 点击过程中发生超时、导航等情况，无法确认完整输入回执；不能自动重试 |

普通 `binding.click(page)` 只做定位后点击，用于机制消融；需要输入阶段防护时使用 `guarded_click`。两者都不会自动重试。

## 保留的限制

- 这是业务页面变化防护，不是隔离的安全执行环境；页面脚本可以干扰运行在页面中的监听器。
- 可见身份不是业务正确性。相同页面外观下改变处理函数，或者处理函数内部先修改身份再写入，仍可能造成错误效果。
- 只覆盖顶层 HTML 常见控件和一个保守的可访问名称子集，不等同于浏览器完整 AX 名称算法。
- 文本后备会保留金额等可能变化的字段；它不会猜哪一个唯一字符串是永久业务 ID。
- 新增身份链接、改变上下文层级或完整网址都可能导致拒绝。不会自动改写查询参数以跨账号或跨会话重放。
- 不提供跨进程幂等、服务端事务或“恰好一次”保证。此前 V7/V8 恢复原型仍独立保留，尚未自动组合成业务承诺。

执行前验证已有研究：[Atomicity for Agents](https://arxiv.org/html/2603.00476v1)明确讨论了验证后仍存在的时序空隙。V9 检验的是事件传播期间核验与自动上下文绑定的实际组合价值，**不把 MutationObserver、重放或执行前检查称为首创**。[workflow-use](https://github.com/browser-use/workflow-use)已经支持语义工作流和无 AI 重放；本项目也不把“不调用模型”本身当成新能力。
