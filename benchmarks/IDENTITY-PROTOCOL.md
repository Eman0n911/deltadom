# 动作身份诊断 v1（执行前固定）

问题：按钮 DOM 对象不变，但它所代表的记录或金额变化时，当前操作核对是否会发现？本实验只诊断机制，不评估模型，也不代表 Browser Use / Stagehand / agent-browser 的任务成功率。

任务固定为“批准 Invoice A，金额必须是 100”。页面初始包含 A/100 和 C/100；每个分支在独立页面中运行，观察后注入一次确定性变化，再执行一次点击。浏览器点击超时统一 300 ms，无重试、恢复或模型调用。页面内部日志只用于事后评分，不提供给操作分支。

四个分支：

1. `deltadom_target`：0.4 现有 `act` 目标及子树核对。
2. `whole_page_guard`：实验性全页快照相等检查，再调用现有 `act`。
3. `row_guard`：实验性订单行完整子树相等检查，再调用现有 `act`。
4. `semantic_locator`：强简单基线，Playwright 精确可见订单名 A + 精确可见金额 100 约束行，再寻找 Approve 按钮；不用位置、隐藏属性或评分日志。显式条件是人工提供，**不含自动生成能力**。

固定八种变化：无变化、相邻订单名变 B、相邻金额变 900、行外计数器变化、行内无关更新时间变化、整行同内容重建、两行重排、只改变页面 JS 中的真实操作对象（可见页面不变）。最后一种是可观测性反例，不能凭 DOM 证明后端行为。

每个分支报告：正确执行数、错误实体/金额执行数、有正确可操作对象却阻断数、没有正确对象而阻断数。拒绝所有动作不能获胜。保存每次完整观察、变化后快照、动作异常与页面实际日志。计时仅是诊断记录，未作性能实验，不作速度排名。

选择标准：若整页/整行检查仅改善当前实现，却比语义定位器多误阻断，就拒绝把它作为核心竞争点。只有自动生成的任务约束能在未见页面上接近人工语义基线、降低现有智能体的错误动作，并有可接受的完成率和开销，才继续讨论产品优势。该自动生成候选在本实验中 **not_run**。

复现（项目开发环境、Chrome）：

```sh
DELTADOM_CHANNEL=chrome .venv/bin/python benchmarks/action_identity_v1.py --output artifacts/benchmarks/action-identity-v1
```

输出目录必须不存在，避免覆盖旧结果。此为 8 个自建确定性反例，不是统计显著性试验或公开 benchmark 分数。
