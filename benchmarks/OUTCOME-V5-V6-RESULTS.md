# 去掉强制契约后的结果：一项窄收益与尚未完成的验证

本轮实现了 V5 独立页面读取和 V6 按写请求触发读取，保留 **17 个完整真实模型回合、1 个额度中断回合、4 个未进入模型决策的启动尝试**。不是全部 BreakingWeb 成绩。所有新模型输入、原始回复、源码副本和已完成回合的评分都在仓库中；没有发布、推送、启用付费积分或换成 API。

## 先说能确认的收益

纠正旧脚手架的单动作限制后，同一 Browser Use 0.13.11 actor、原生默认每轮最多 **5 动作**、总 **40 个实际动作单位**、同一 WorkBuddy Deepseek-V4.1-Flash 通道，在原冻结清单首项 Amazon 正常任务中的结果：

| 分支 | 官方成功 / 声明 | 模型请求 | 实际动作单位 |
|---|---|---:|---:|
| 简单重新读取核对（[f001](../artifacts/benchmarks/outcome-v5/f001/result.json)） | 是 / 是 | 7 | 7 |
| 同样核对 + 合并点击和独立读取（[f002](../artifacts/benchmarks/outcome-v5/f002/result.json)） | 是 / 是 | 5 | 7 |
| 再增加精确实体匹配（f003） | 额度中断，未完成 | 6 个请求、4 个回复 | 不计完整成绩 |

f001/f002 的源码绑定完全相同，两组各一次。这支持“这一回合省了两次模型往返”，不证明总体成功率、费用、延迟或强创新。请求数不是 WorkBuddy 内部全部生成次数；没有 provider token/usage。运行存在交叠，墙钟时间不作速度排名。Amazon 已参与开发，所以这是探索性结果。

**胜出的实现原本是强简单基线 `macro-simple`，现将它采纳为精简核心。没有把原先的身份匹配算法改名宣称胜出。** 原生框架也能批处理动作，本次模型实际选了什么会影响请求数；这里不是框架理论最优效率的比较。

## 为什么以前输给简单核对

1. 用户要求“现在符合条件”，旧版却强制证明“之前没有，之后新增”。多出准备、两次导航和模型决策，已有正确状态也被拒绝。
2. 准备和核对改变工作页面，导致旧节点引用失效、返回和重复观察；对未保存表单也不合适。V5 把读取放在独立临时页面，原页面不因核对而导航。
3. 不同页面不一定有相同的文本字段或 main 区域；模型编写 CSS/属性契约增加失败点。V5 只保留可观察对象的可选匹配，其他情况返回普通可见页面证据。
4. 工具没有明确表达读写时序。模型曾把实际的点击后独立读取误认成点击前观察，又多刷新一次。V5.1 增加真实时序元数据，并向两个合并工具分支给出相同说明。
5. 旧脚手架把 Browser Use 每轮动作上限设成 1，而已安装版本默认是 5，会放大合并工具的请求数优势。V5.2 恢复 5，并把原生 `done` 的顺序保护同步到自定义 `finish`，避免把未观察的结果预先声明为成功。

没有通过多试三次、识别某个干预的失败次数或更换样本修正这些问题。

## V6 做了什么，验证到哪里

V6 不再增加一个需要模型选用的动作工具。它包住原有动作：记录动作执行窗口内当前页面的 POST/PUT/PATCH/DELETE 请求生命周期，等已观察请求结束后，附上一份新加载 UI 文档的内容。只用请求方法和结束事件，不读响应正文、后台状态或评分器。未观察到这类请求时跳过额外读取；运输完成不等于业务成功，延迟任务也不受保证。没有自动写入重试。

强对照同时保留：简单重读、相同合并工具、每次非链接点击均读取的程序化方案；所有组保留原生 5 动作能力和相同总预算。V6 的 [56 个计划模型单元](../artifacts/benchmarks/outcome-v6/summary.json) **尚无已完成成绩**，不能借用 V5 的数字。

已完成的非模型验证：

- 固定 7 网站、正常/干预共 **14 个 UI 读取检查**：与独立编写的精确 URL/名称核对一致，原页面文档和 URL 保留，临时页面关闭。无实体链接时返回完整视图，不伪造成员证明。首次失败和修复均保留在 [机械记录](../artifacts/benchmarks/outcome-v5/mechanical-r3.json)及修订说明中。
- BreakingWeb 邮件和购物这两个已用开发场景 × 2 条件 × 3 程序化分支，共 **12 个单次写入检查**。每格只调用一次写入；正常条件目标在独立 UI 读取中出现，干预条件未出现。8 个自动读取格均捕获恰好一个写请求，并在其结束后开始读取。三组信息一致，**不是 12 个自主任务成功，也不是候选胜出**。[全部证据](../artifacts/benchmarks/outcome-v6/single-write-r2.json)
- V6 当前自动读取的是操作后的当前视图。购物的目标在购物车，所以源商品页的读取本身不能证明加购完成；显式结果页核对仍然必要。这项限制被保留，没有把控制器额外读取的购物车真值送给候选。
- Python **47 项测试通过**；改动 Python 文件通过 Ruff。覆盖乐观假成功、延迟写入、读取预算耗尽、原页面未保存内容保留、重复链接与数量区分、失败/跳转不当作缺失、事件监听清理。
- 真实 Browser Use 点击工具 → 请求结束 → 独立 UI 读取 → 原生 MessageManager 的 **2 个集成检查通过**，正常与干预的完整 payload 均进入原生 read-state。没有调用模型，也不作为模型分数。[集成证据](../artifacts/benchmarks/outcome-v6/native-integration.json)
- 独立测试了模型渠道中止：保存部分历史、退出并跳过官方评分，不能把额度阻断记作候选失败。
