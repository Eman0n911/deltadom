# Exhaustive original-site button input audit

Freeze every native BUTTON node in all original seven-site clean/intervention
initial views, seed 42, before clicks. Do not filter by candidate support, duplicate
labels, expected benefit, or success. Retain zero-button views (LMS). Record XPath,
name, original task/condition, and capture errors. Frozen inventory separate from
results. Each button/arm gets a fresh upstream session and one attempt.

Arms: installed native history matching + real Tools.click; independent full-row
text + exact accessible button-name Playwright check (same simple algorithm as
V9 extension, supplied the native observed accessible name for icon controls);
automatic binding + trusted dispatch guard. One demonstration capture, rotate
semantic siblings exactly as in coverage, then actual click. No forced timing
races or site patches. All sites and original conditions remain unchanged apart
from this explicit DOM-order perturbation. No LLM, retry, or official task grader.

Observe the actual clicked DOM node in an independent window capture listener;
retain events' isTrusted and whether target equals the demonstrated node. A guard
refusal may prevent propagation after this observer, so keep attempted events and
refusal separately. This measures input identity and coverage, not server effects,
full task completion, or autonomous model success. Native missing selector and
page/snapshot errors remain in denominator. Node identity is valid because this
experiment moves existing nodes, not remounts; synthetic remount matrix is separate.

An input is counted correct only when an unblocked attempt was observed on the
exact demonstrated button, with no other button clicked. Missing input counts
as refusal, not success. Record elapsed capture/dispatch time descriptively only.
Do not select the best repetition or claim formal speedup from this local audit.
