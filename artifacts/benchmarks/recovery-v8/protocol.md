# V8 browser-internal replay — fixed before implementation

Hypothesis: V7 callback admission cannot prevent duplicate HTTP writes generated by
one page action or resumed page code. Add persistent request forwarding admission.
Fingerprint exact method + URL + body bytes, bound to a V7 intent and held resource.
Persist BEFORE network forwarding; never refund on transport error. This provides
at most one forwarding admission per exact fingerprint, not server exactly-once.
No response bodies, private APIs, or scorer data are provided to the component.

Compare native Playwright single callback, V7 resource journal single callback,
in-memory exact request gate, V8 durable exact request gate. Same browser, UI and
request schedule in all arms. Synthetic local HTTP server ground truth stays with
the evaluator. Eight fixed cases: single; parallel identical requests; lost reply
then page retry; new browser context replay; different bodies; semantically same
JSON with different bytes; legitimately repeated identical increment; 307 redirect.
Retain negative cases: byte fingerprints cannot infer semantic equivalence or
whether an identical request is intentional. Redirect chains may bypass route
callbacks. Blocking legitimate repeats is a failure, not a safety win.

No sleep/retry tuning: two request attempts in duplicate/retry cases, one original
request for single/redirect, two distinct desired effects in different/legitimate.
Score server effect count vs declared desired count, false blocks, extra effects,
forward decisions. No model/task efficacy, no claim of algorithmic originality.
V7's 48-cell diagnostics and original BreakingWeb matrix remain unchanged.
